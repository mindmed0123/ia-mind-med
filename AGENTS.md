# Project rules
- Keep CRM report model selection separate from the existing CRP generation branch; Psychology remains unchanged.
- Share report model definitions between UI and edge generation so inference rules cannot diverge.
- Resolve report models server-side from owner-scoped custom models and organization policy; client input cannot override a locked organization.
- Persist the selected model snapshot and scope version with each generated CRM document and its audit entry.
- Store document formatting independently from clinical models and apply it to both report and prescription exports.
- Keep legacy migration history and generated schema types intact when Cloud blocks destructive retirement; report incomplete deletion rather than rewriting history to hide references.- Partner restrictions live in a secret-free shared catalog read by model resolution, UI and SQL; the partner restriction is the final override in model resolution and the partner link on profiles is server-written once.
- Specialty template AI instructions are server-only: clients get column-limited catalog access and generate-laudo reads instructions with the service role.
- Billing, admin-mutation, quota-by-id and e-mail-queue DB functions are service_role only; edge functions call them after their own auth check.
- Edge functions build return/invite URLs only via _shared/allowed-origin and fetch only this project's storage paths via _shared/storage-url, never caller-supplied URLs.
- Client uploads to the audio-files bucket go under `<auth uid>/...` and PDF exports download before any best-effort archive upload; storage policies key on the first folder.
- Audio transcription goes through the Lovable AI Gateway via _shared/gateway-transcribe (pinned npm SDK import in Deno); no OpenAI key is used, so costs land on workspace credits.
- Paid access mirrors Stripe through _shared/stripe-subscription-sync, used by both stripe-webhook and sync-subscription; the app calls sync-subscription after checkout and before denying access, so access never depends on webhook delivery alone.
- AI-spending edge functions check plan entitlement server-side via _shared/entitlement (UI plan checks are UX only); scheduled jobs call service-role-only functions with the vault service key.
- Checkout reuses a Stripe customer only when it is stored for the user or tagged with metadata.user_id; never an untagged e-mail match.
- Every clinical PDF download/print goes through src/lib/pdf-delivery (A1 signing, download, audit); never call downloadPdf directly from screens.
- A1 certificate signing runs only in the browser (node-forge + pdf-lib); the .pfx may be kept in IndexedDB, the password and decrypted key never leave memory or reach the server.
- Copies, downloads, prints, signatures and saves are logged via the log_document_activity RPC into immutable audit_logs, with content SHA-256 and request IP.
- Terms acceptance goes through the accept_terms RPC; bumping TERMO_VERSAO in src/lib/termo-adesao forces every user to re-sign.
- The medication catalog is cross-checked against ANVISA open data; only entries with an active registration stay ativo, and CID only ranks results, never filters them.
- Medical report PDFs are drawn as vector pages by src/lib/laudo-pdf from the structured document export-pdf builds with _shared/laudo-document (shared so server and tests use the same mapping); CRP session records keep the legacy HTML path.
